## 3. 방 하나, 보병만
- [x] 경기용 바이너리 인코딩(양자화) + 테스트 (`src/net/matchProtocol.ts`: 입력 28바이트, 병사 16바이트, 내 병사 32바이트)
- [x] 입력: 스텝마다 번호, 한 프레임 것을 묶어 보냄(TCP라 반복 전송은 안 함). 브라우저도 양자화된 값으로 스텝을 돌려 서버와 똑같이 계산. 서버는 순서대로 한 틱에 하나(밀리면 둘)
- [ ] 입력 서버 검사(속도, 연사, 탄약, 회전): 지금은 서버가 같은 규칙으로 직접 돌리므로 속도·연사·탄약은 서버 값이 기준. 회전 속도와 사격 방향 검사는 보안 단계에서
- [x] 내 병사 예측 + 서버 결과로 보정 (`NetMatch.correct`: 서버가 마지막으로 처리한 입력 때의 위치 차이만큼 옮김; 로컬 시험에서 22 m 달리는 동안 오차 2 mm 이하)
- [x] 스냅샷 20 Hz, 병사마다 한 번 인코딩, 보간 100 ms (관심 범위는 6번 단계에서)
- [x] 이벤트: 처치, 명중 표시, 피해 방향, 배치, 다운/부활/사망, 점령, 모드, 점수 팝업, 경기 끝 (JSON `ev`); 거점·규칙·점수표는 초당 4번 (`mstate`)
- [x] 사격 판정은 서버, 지연 보상: 병사 자세를 80틱 기록, 쏜 사람이 본 틱(최대 0.3초 전)으로 되감아 히트박스를 계산으로 판정(`rayHitbox`, `MatchSim.casterFor`). 탄 퍼짐은 목숨마다 같은 시드로 양쪽에서 같게
- [x] 다른 사람 병사 모델, 총구 화염, 총소리, 예광탄(보이는 시점에 맞춰)

## 5. 나머지 게임 요소

- [x] 의무병 구급상자·지원병 탄약 건네기(사람끼리, E): 필요한 사람은 스냅샷 표시(`SF.needMedkit/needAmmo`)로 안내
- [x] 가젯, 건설, 보급소: 공통 코드 `src/sim/kit.ts`(서버가 실제로, 브라우저는 같은 코드로 예측). 건설 자리는 양쪽이 같은 계산으로 만들어 id가 같음(`fortPlanFor`), 상태는 `mstate.fort`로; 로켓·소총 연막·비콘·지뢰는 스냅샷 `things`로 그림, 폭발은 시점 맞춰 표시; 비콘 배치는 같은 편 누구나(분대가 아직 없어서)
- [ ] 차량(운전자 예측, 서버 검사), 비행기
- [x] 분대: 서버가 편마다 4명씩 들어온 순서로 묶음(첫 사람이 분대장), 분대원 옆 배치, 분대 전멸 시 +5초, 비콘은 분대만
- [x] 콜인: 분대장만(B 메뉴, 서버가 RP·쿨다운 판정), 포탄·연막은 서버 폭발로, 정찰기·보급상자·표시 기둥은 서버가 알린 호출을 브라우저가 따라 그림, 정찰기에 찍힌 적은 그 편 미니맵에, 보급상자는 서버가 나눠 줌. 로켓 전차는 차량이 서버에 들어올 때
- [ ] 봇 계산 분산(같은 팀 PC가 분대 단위로), 아무도 못 맡으면 서버가 LOD로
